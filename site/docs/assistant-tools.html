Everything here is stored on your own machine, in the same SQLite file as your tasks.

What the Assistant sees

What the Assistant is told about its tools. It gets the summary on every turn: the buckets, and each tool's name and what it needs. It asks for the detail of a bucket (tools.list) or a tool (tools.describe) only when a turn needs it. Everything it can change, it brings up for you to press: the button that does it, lit, or the page that holds it. On a phone it asks yes or no.

Table#

Decide about the item on the table.

reply#

The "Reply" button: write a reply to the sender. Nothing is sent.

  • text - the gist, in the owner's words
  • cc (optional) - people to loop in on it, by name or address ("loop Gail in and ask her" is a reply with Gail copied, never an agent)

At once - a draft, nothing sent.

approve#

The "Send" button ("Approve" on an agent's proposal or a task's close-out): the owner's yes to what is drafted on the item: sends the reply as it stands - on a task's close-out it merges the pull request or closes the issue FIRST, then sends the reply; on an agent's proposal it runs that action and only that. It never closes the task - that is close, the owner's own Mark done, a separate step - and never continues an agent's session - that is agent.continue.

Brings up its button for you to press.

redraft#

The "Redraft" button ("Draft with AI" when nothing is drafted yet): write the draft again.

  • text - the change

At once - a draft, nothing sent.

mine#

The "Put it on my list" button: make it a task on the owner's own list - no agent.

Brings up its button for you to press.

regular_agent#

The "Send to agent" button: send it to an agent that does not write code - it becomes a task of its own. Never for Taskuary's own settings, connections or update: those are its own screens (app.find), nor for setting up a meeting: meeting.new.

  • text - the job
  • as (optional) - a profile from agents.list, only when one fits
  • new (optional) - true when the job is NOT about the item on the table

Brings up its button for you to press.

coding_agent#

Pipe#

The walk and sets of items, and filing mail.

pipe.clear#

Clear a SET of items from the pipe at once - takes select (below); read, never deleted. "Clear all the FYI" and "mark the FYI read" - one FYI on the table or many - are this with kind: fyi, never next. Their words naming the set are the press: it is marked read at once and the count said - ALL in their words is every one waiting, never just the batch on the table. It only clears: when the owner says "from now on" too, also CALL preference.exclude_sender or preference.sender_rule.

  • select - below
  • scope (optional) - all (the default - every one waiting that select matches, the batch on the table and every one after it: "all the FYI", "mark every FYI read", "ignore all the FYI") | table (only those on the table: "mark these read", "these four")

Runs at once and says what it changed.

pipe.defer#

Put a SET away until a day. Runs at once and the count is said.

  • select - below
  • until - (as task.defer takes it): "snooze everything from Gail until Monday" is select sender: Gail

Runs at once and says what it changed.

pipe.close#

Close a SET at once. "Close all the tasks from Priya" is select sender: Priya. Runs at once and the count is said.

  • select - (below): each task in it is marked done, each notice read

Runs at once and says what it changed.

pipe.remove#

Not ours for a SET at once - "dismiss the spam", "get rid of these newsletters" - then triage learns from each; otherwise it teaches nothing. Never touches work waiting on the owner, an agent at work, a draft waiting for its Send or a goal - those are left and said. Runs at once; the receipt lists every row as its link.

  • select - (below; keys: the rows you judged, from pipe.read): each mail is filed, each task removed (Remove - not a task), nothing deleted
  • learn (optional) - true only when the owner says "from now on" too

Runs at once and says what it changed.

pipe.block#

Stop a SET's senders for good - only when the owner says so ("and stop them", "block them", "unsubscribe me"). "Dismiss the spam" alone is pipe.remove, never this.

  • select - as pipe.remove takes it
  • how (optional) - rule (the default: an exclusion rule per sender in Settings, their mail never reaches triage again) | unsubscribe (a mailing list: its Unsubscribe comes up lit, one list at a time - the owner presses it)

Runs at once and says what it changed.

SOUL and COUNSEL are added to, never rewritten; a fact about their job or about what becomes a task is care or work, never these. Who reports to whom and who owns what is people.relate.

  • note - it, in the owner's words ("Gail moved to Ops", "Ray handles payroll for me", "I put renewals off to Friday", "I don't care about the legacy export job any more")
